# Preview access rollout

The live Android preview remains a separate two-device lab. No product app page links to it. Admin → Tenant workspace now lets an administrator mark either staged Android app as available to all organizations (Shared pool) or only to the selected organization. The choices are independent: disabling Shared pool does not remove an organization's own grant. The live entitlement table starts empty, so neither app is available to tenants by default.

The current staged registry is `lib/preview/staged-apps.ts`: Wikipedia (`org.wikipedia`) and AntennaPod (`de.danoeh.antennapod`). This is deliberately narrower than Northstar's app research catalog. A research listing does not imply that an APK has been provisioned or that a visitor may preview it. Keep the registry aligned with the lab's checksummed APK catalog and worker package allowlists; replace both static registries with a shared provisioning record before scaling beyond the lab.

`db/migrations/20261002_preview_app_entitlements.sql` was applied to the production Supabase project on 2026-10-02. It adds no initial assignments and grants no direct access to `anon` or `authenticated`. The Admin API uses the service role after checking the signed-in user's admin role. `POST /api/preview/access` uses the signed-in user's `customer_id` and only enabled global or matching organization rows to create a five-minute HMAC grant. The browser never supplies the tenant or package list. `NORTHSTAR_PREVIEW_GRANT_SECRET` is configured in Vercel Production; do not log or return it.

On the Hetzner capture host, separate grant and broker-to-worker secrets were staged in `/etc/northstar-preview/` with `root:northstar` ownership and mode `0640`. They are **not active in the live preview services**. The broker and workers still bind to loopback and the local SSH-tunnel lab keeps its diagnostic behavior. The three capture emulators are separate from preview emulators and were not modified by this rollout.

Before enabling tenant previews, add an authenticated visitor page that obtains the grant from Northstar without putting it in a URL, passes it to the broker for both catalog and allocation, and retains the worker session token only within that visitor's browser session. Add TLS routing for the broker and worker WebSockets, allow only the explicit visitor-page origin, activate both host secrets together, and refuse direct worker allocations. Do not expose ports 18080–18082 publicly or activate the secret mode while the anonymous local lab still depends on it. Then verify two real tenant accounts: global app visible to both, organization app visible only to its assigned tenant, unauthorized allocation refused before a worker is contacted, one viewer per device, and a full wipe before the next visitor. Login-gated apps must remain previewable with the visitor's own account and must start from a clean guest state.

Validated on 2026-10-02: production Admin loaded the unassigned staged apps and their icons in Chrome, switching organizations updated the panel, the schema migration ran successfully, the Next.js production build passed, and the separate lab broker plus two workers and emulators stayed active. The TypeScript entitlement test checks global and tenant isolation; the Python grant tests check signatures and package isolation. No real tenant entitlement was enabled and no visitor preview was launched through Northstar yet.
