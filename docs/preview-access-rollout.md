# Preview access rollout

The Android preview remains separate from product app pages while we validate it. Admin → Tenant workspace lets an administrator mark either staged Android app as available to all organizations (Shared pool) or only to the selected organization. The choices are independent: disabling Shared pool does not remove an organization's own grant. The live entitlement table starts empty, so neither app is available to tenants by default.

The current staged registry is `lib/preview/staged-apps.ts`: Wikipedia (`org.wikipedia`) and AntennaPod (`de.danoeh.antennapod`). This is deliberately narrower than Northstar's app research catalog. A research listing does not imply that an APK has been provisioned or that a visitor may preview it. Keep the registry aligned with the lab's checksummed APK catalog and worker package allowlists; replace both static registries with a shared provisioning record before scaling beyond the lab.

`db/migrations/20261002_preview_app_entitlements.sql` was applied to the production Supabase project on 2026-10-02. It adds no initial assignments and grants no direct access to `anon` or `authenticated`. The Admin API uses the service role after checking the signed-in user's admin role. `POST /api/preview/access` uses the signed-in user's `customer_id` and only enabled global or matching organization rows to create a five-minute HMAC grant. The browser never supplies the tenant or package list. `NORTHSTAR_PREVIEW_GRANT_SECRET` is configured in Vercel Production; do not log or return it.

On the Hetzner capture host, separate grant and broker-to-worker secrets live in `/etc/northstar-preview/` with `root:northstar` ownership and mode `0640`. On 2026-10-02, preview device 2 was placed behind a tenant-only broker on loopback port 18083. Caddy serves the isolated viewer at `/preview/`, routes its signed catalog/allocation requests to that broker, and exposes only device 2's authenticated `/stream` over WSS. Public direct access to the broker and workers' loopback ports is still blocked. Preview device 1 continues to serve the existing local lab session; the three capture emulators are separate and unchanged.

The browser viewer receives a grant through a checked `postMessage` from the authenticated `/preview-lab` Northstar page; the grant is never put in a URL. It sends the grant to the broker for allocation. The worker lease travels in the WSS subprotocol, not a URL query, in tenant mode. The visitor page refreshes the short-lived grant and shows only apps returned for that user's workspace. The iframe has a `frame-ancestors` policy limited to Northstar and local development origins. No product app page links to this route yet.

The private route is a controlled integration test, not the final product cutover. Before replacing Screen viewer, verify two real tenant accounts: a global app visible to both, an organization app visible only to its assigned tenant, unauthorized allocation refused before a worker is contacted, one viewer per device, and a full wipe before the next visitor. Confirm login-gated apps can be explored with the visitor's own account, refine capacity and queueing, and test responsiveness in Chrome. The existing Screen viewer must stay available until those checks pass and the replacement UX is approved.

Validated on 2026-10-02: production Admin loaded the unassigned staged apps and their icons in Chrome, switching organizations updated the panel, the schema migration ran successfully, and the Next.js production build passed. The tenant broker denied an unsigned catalog request, returned only the signed package, refused an unauthorized package, and allocated an idle device that streamed a real JPEG frame over WSS before resetting. The TypeScript entitlement test checks global and tenant isolation; the Python grant tests check signatures and package isolation. A signed-in Graet tenant browser showed no apps before assignment and only Wikipedia after Admin enabled its organization grant. The visitor opened a private device in Chrome and interacted with Wikipedia's onboarding, Home, Search, Back, and scrolling. Frame rate varied during this run, so responsiveness still needs further tuning. A second real tenant account and a clean next-visitor wipe check remain before cutover.
