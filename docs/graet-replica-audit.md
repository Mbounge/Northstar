# GRAET replica capture audit

The required per-page review process is in [graet-replica-workflow.md](graet-replica-workflow.md).

This local replica is judged against the current 95-screen iPhone browsing release in the GRAET tenant, now also loaded into Test. The local files in `public/graet-replica/captures` are working copies of those tenant captures, not an alternate source of truth. A route is complete only when its initial view, every captured scroll position, visible controls, back behavior, and return scroll position match the capture. Code compiling is not a visual pass.

Missing destination captures do not block a working simulator: use mock records in the appropriate shared page component, with behavior consistent with the captured family. The main completion work is replacing screenshot-backed rows and hit areas where data or state must vary, completing distinct action outcomes (for example, trial start versus dismissal), and visually checking every family with multiple records, tabs, and scroll positions. Lack of a capture limits claims of exact visual equivalence for an unseen destination; it does not justify leaving that route unfinished.

For each screen, use this sequence: identify the exact current-tenant capture and viewport; align the first frame; map scroll-overlap anchors before stitching later frames; infer gestures from adjacent captured states, such as horizontal calendars and vertical content; turn repeated elements into shared components with captured data; wire visible controls to their destinations; compare the running 375 × 812 viewport at top, intermediate, and bottom scroll positions; test navigation out and back. Where content is missing, simulated data may complete a view, but captured names and scores remain unchanged. Never promote a screenshot taken during a transition to a stable scroll state.

The current 95-screen iPhone browsing release has no own-Profile destination capture. The older Test release is not evidence for this release. The Profile tab now opens the shared component with clearly simulated personal fields so the navigation can be exercised, but its data and visual details cannot be certified as captured 1:1.
