# Codex subagent testing

Open `/canvas-v2-e2e/codex-subagent` on the local development server with `NORTHSTAR_E2E=1`. Production returns 404. This is a test transport, not a new customer provider.

The ordinary Northstar session host, prompts, dynamic tool definitions, browser tool executor, source guards, renders and visual-review packet builder remain in use. Instead of spawning the API-authenticated CLI, the model transport exchanges files with an explicitly created Codex subagent. No API key is read. `read_source` and `inspect_image` use the same bounded public-media reader as production, including address, redirect, format and byte limits; this supports actual public font and reference discovery without a paid model API. Hosted workspace operations remain disabled. Image generation uses the explicit built-in relay described below. `prepare_asset` runs the same deterministic production crop script locally with retained image bytes. Set `NORTHSTAR_SUBAGENT_PYTHON` to an absolute Python executable with Pillow; missing configuration fails clearly and never falls back to an API. Arbitrary workspace/model-authored shell commands remain disabled.

Transport sessions are archived under the system temporary directory's `northstar-subagent-relay/session-*`. Each has:

- `configuration.json`: the exact Northstar developer instructions and registered tool schemas; an empty tool list identifies a reviewer session.
- `inbox.json`: current exchange, turn, input or actual tool result, and the response path.
- Original attached images and materialized tool-return images, without resizing.
- `transcript.jsonl`: each accepted exchange. No account/login key or public session token is logged.

For exact model matching, dispatch **gpt-5.6-luna / high**, matching the production default and relay protocol identifier. The controlling conversation must separately record the actual dispatched model: the relay's model identifier does not verify the subagent's model. Runs dispatched to **gpt-6-luna / high** exercise the shared workflow but do not establish model-version parity. Give it only the relay session path and an instruction to read the configuration and current inbox, view supplied images, then submit one action. Its native shell/file tools are used only to read this exchange and write a response; they must not construct or edit the prototype directly. Every prototype edit must be a Northstar tool request, executed by the app. Native Codex instructions cannot be removed, so this is a workflow test, not an assertion of identical model context.

Prefer `scripts/northstar-subagent-reply.mjs SESSION EXPECTED_EXCHANGE ACTION_JSON`. Write only the action to ACTION_JSON, and pass the exchange ID you actually assessed. The helper reads the turn/exchange IDs and response path from the current inbox and rejects stale/stopped exchanges. This avoids hand-copying IDs between primary and reviewer sessions. If directly writing an envelope, use this shape atomically at `inbox.responsePath`:

```json
{"exchangeId":"from inbox","turnId":"from inbox","action":{"type":"tool","name":"canvas_read","arguments":{}}}
```

Other actions: `{"type":"message","text":"brief progress"}` and `{"type":"finish","text":"final answer"}`. Both message and finish require `text`. The helper validates before writing and reports `status:consumed` only after the exact exchange appears in the transport ledger. A written reply without acknowledgement is not completion; consumption confirms delivery, not tool execution or quality approval. A consumed exchange can remain visible while its tool or review runs. Wait for a new exchange; never replace its action. The helper rejects a different pending/consumed action and permits an identical retry without executing twice. Read the next inbox only after the exchange ID changes. Consume tool failures as real failures. Journey replies begin with a verification summary; inspect `state.journey.passed` and every requested step. Failed journeys return `success:false` while retaining their actual trace and pixels. Tool delivery/helper acceptance does not mean a visual or interaction check passed. Include any steering input. Stop when inbox says interrupted, closed or completed. Never reuse a response for a new exchange/turn. Unknown tools and mismatched IDs fail closed.

Reviews use **separate sessions and separate subagents**, with their actual review instructions and images. Initial review uses the selected effort (high when no effort is supplied); final review requests the selected effort. This manually dispatched test route allows up to five minutes for each review, including initial appearance. Its browser tool-result request allows 330 seconds so that it does not cancel that review at the ordinary 60-second client deadline. Production retains its 45-second initial check and 120-second reviewer transport deadline. This accommodation is for orchestration overhead, not a performance improvement or customer setting. If a review misses the test deadline, Northstar reports it unverified; it does not fabricate approval. This harness does not itself schedule subagents: the controlling Codex conversation must dispatch and supervise them. Before attributing results to a harness instruction change, compare the session’s retained `developerInstructions` with the current `NORTHSTAR_AGENT_INSTRUCTIONS`. Existing conversations keep the configuration they started with. Archive the committed sources and use a fresh workspace session when testing changed base instructions; a fresh turn in an existing conversation is not a fresh instruction configuration. Prepared drafts supplied by other agents test commits, runtime and review, but must be labeled as assisted revisions rather than unassisted end-to-end author generation.

This tests decisions, asset handling, real tool execution and rendered outcomes using Codex inference. It does not verify API billing, provider latency, streaming token timing, account login, production rate limits or provider failures. Scripted responses are transport tests only. Quality conclusions require a real subagent to author through Northstar and an independent visual review.

Large saved boards use the shared production snapshot codec: repeated inline media are stored once and the JSON source is compressed losslessly in the encoder worker. The outer archive remains JSON, and both production session loading and this test route support packed archives plus legacy schema1 files. Storage limits apply to the encoded archive; expansion is bounded and verified before accepting saved source. Use the asynchronous snapshot reader/importer for packed files. Presentation mode now still reports failed saves, and Fast Refresh must preserve the newer live workspace instead of hydrating an older checkpoint over it. A Saved indicator is not a substitute for a reload/asset-preservation check.

Run `/canvas-v2-e2e/prototype-quality` for deterministic checks against the real private screen runtime: blocked/partially covered controls, overlay stacking, no-op navigation, connected mock save/reopen, and measured fixed/sticky scroll behavior. This suite makes no model calls and does not establish reference fidelity. Browser screenshots and traces should be archived alongside genuine author/reviewer sessions.

`generate_image` now follows a test-only built-in-tool relay, preserving the normal Northstar author request, creative job polling, generated-asset factory and client registry. It does not call the paid image API or require an API key. The author requests `generate_image` through Northstar and waits for its normal tool result. The controlling Codex conversation executes that exact immutable pending request with `image_gen.imagegen`; it must not choose replacement prompts or externally curate/source an image. This remains manually dispatched test transport, not production provider parity.

Run `node scripts/northstar-imagegen-pending.mjs` to list active image jobs. Before invoking the built-in tool, claim the job with `node scripts/northstar-imagegen-pending.mjs --claim JOB_PATH EXPECTED_REQUEST_HASH`. Invoke the returned `request.toolArguments` exactly, including approved input image paths for an edit; a new image has no referenced paths. An `already-claimed` job must recover its existing tool result instead of generating again. Submit only the actual tool-returned PNG with `node scripts/northstar-imagegen-reply.mjs JOB_PATH EXPECTED_REQUEST_HASH ACTUAL_TOOL_PNG`. If the built-in tool returns PNG data rather than a local path, save those exact returned bytes as PNG first. The helper binds the result to the call/nonce/request hash, rejects stopped/stale/replaced outputs and verifies PNG format, bounds, bytes and hash. The accepted output is packaged by the existing `creativeArtifact` factory as generated/inferred media, with original input IDs and image request provenance; the shared Northstar client registers it normally. The author must inspect the retained pixels and bind the returned asset itself.

The built-in tool has no direct equivalent of the production image API’s `size` and `quality` controls. Requests retain those fields, and results report the actual PNG dimensions and this limitation; do not claim those API settings were exercised. Exact prompt, approved input hashes, claimed job, artifact hash and transport result files remain in the temporary image relay for audit. Stop cancels the pending job; a late result cannot be published as a generated asset. Protocol fixture PNGs in automated tests verify transport and packaging only; they are not genuine generation, visual craft or product evidence. Actual generation occurs only after the author requests it.

The image relay wait is bounded to ten minutes to cover built-in generation and manual dispatch. The shared creative client polls small running/completed receipts every900ms; its per-request30s timeout and post-result review delivery timeout do not bound total generation time. This transport awaits a pending tool before delivering the next author exchange; it does not claim concurrent background authoring of another app in that same exchange. Independent work can continue in other explicitly authorized tasks while the image request is pending.

The globally cached test host refreshes its creative factory on each route request so a newly created session receives current image relay support after development HMR. Existing sessions retain their original creative runtime and in-flight jobs. Reloading source or beginning another turn in an existing session does not retrofit that session; use normal Stop/close and a new session when testing updated creative transport. The regression exercises normal host/client creation before and after factory refresh and verifies that the old session remains unchanged while the fresh session reaches the image job relay.
